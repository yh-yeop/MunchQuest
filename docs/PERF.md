# 성능 측정

`node bench/server.mjs [명수...]` — 접속자 N명을 사냥터 두 곳에 반씩 두고 60초(1200틱) 동안 걷고 쏘고 구르게 한 뒤,
틱 하나 처리 시간(메시지 JSON 직렬화 포함)과 접속자 한 명이 받는 양을 잰다. 숫자는 이 컨테이너(Node 22)에서 잰 값이라 절대값보다 비교용.

## 2026-11-21 스냅샷 줄이기

| | 줄이기 전 | 뒤 |
|---|---|---|
| 10명 · 스냅샷 평균 | 634B | 403B |
| 10명 · 한 명이 받는 양 | 12.5KB/s | 8.0KB/s |
| 30명 · 스냅샷 평균 | 1347B | 663B |

| 30명 · 틱 평균 / p99 | 0.23ms / 0.37ms | 0.16ms / 0.44ms |

바꾼 것
- 다른 사람 줄은 보간에 필요한 것만 (좌표는 0.1px 반올림, 공격 대기 · 구르기 방향 같은 예측용 값 빼기). 내 정확한 몸 상태는 받는 사람마다 `you` 로 따로.
- 이동 · 구르기 방향을 서버 · 클라이언트가 똑같이 0.001px 단위로 끊는다 (`sim.js`). 예측은 그대로 맞고(되맞춤 0회 시험 통과) 좌표가 18글자 → 7글자.
- 몬스터 종류는 이름 대신 번호(`MOB_TYPES`).

틱 비용은 30명이어도 1ms 아래라 Durable Object 한 채널(30명 한도)에 여유가 크다. 대역폭이 먼저 한계가 된다.

## 클라이언트 프레임 (2026-11-21)

디버그(F3) 패널에 `프레임 · 그리기` 시간(ms, 지수 평균)을 띄운다. 헤드리스 Chromium, 960×540, 혼자 테스트(방장 = 이 탭)에서 초원에서 사냥하며 12초 뒤:

| 사람 | 프레임 | 그리기 |
|---|---|---|
| 4 (나 + 봇 3) | 0.37ms | 0.30ms |
| 30 (나 + 봇 29) | 0.6~0.8ms | 0.5~0.65ms |

16.7ms(60fps) 예산의 5% 아래. 30명이 몰리면 이름표가 화면 위까지 탑처럼 쌓이던 것을 원래 자리에서 48px(세 줄 남짓)까지만 쌓고 나머지는 숨기게 고쳤다 (`src/tags.js`, 내 이름표는 늘 보임).

## 몬스터는 바뀐 것만 (2026-11-21)

몬스터 줄은 지난번 보낸 것과 달라진 것만 보내고, 1초마다 한 번(그리고 맵에 막 들어온 사람에게) 전부 보낸다(`mfull: 1`). 쓰러진 몬스터는 `die` 사건으로 지우고, 다시 태어나면 늘 보낸다.
안 온 몬스터는 클라이언트가 같은 자리를 보간 버퍼에 넣어, 오래 멈췄다 움직일 때 미끄러지지 않는다.

| 사람 (봇이 계속 쏘며 돌아다님 — 몬스터가 거의 늘 움직이는 나쁜 경우) | 앞 | 뒤 |
|---|---|---|
| 1 · 스냅샷 | 324B | 257B |
| 10 · 스냅샷 | 403B | 351B |
| 30 · 스냅샷 / 한 명이 받는 양 | 663B / 14.3KB/s | 618B / 12.9KB/s |

조용한 사냥터(몬스터 대부분이 쉬는 중)에선 몬스터 줄이 거의 0이라 차이가 더 크다. 시험: 지연 150ms로 1분 사냥한 뒤 클라이언트가 보는 몬스터 목록 · 자리 · 체력 · 상태가 서버가 보낸 것과 정확히 같은지 (`test/soak.test.js`).
