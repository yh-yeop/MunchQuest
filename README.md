## M0에서 확인하는 것

| 항목 | 기준 | 상태 |
|---|---|---|
| 같은 방의 두 사람이 서로 움직이는 게 보임 | 탭 두 개 · 인터넷 너머 둘 다 | ✅ |
| 내 이동은 지연이 있어도 바로 반응 (예측) | 지연 150ms에서 끊김 없음, 되맞춤 0회 | ✅ (테스트 · 실제 브라우저) |

| 도트가 뭉개지지 않음 | 480×270 정수 배율, 좌표 정수 | ✅ |

## 해 보는 법

- **혼자**: "혼자 테스트" — 봇 3명이 지연 150ms로 돌아다니고, 내 연결에도 150ms가 걸린다.
- **창 두 개**: 한 창에서 "방 만들기", 다른 창에서 코드로 "참가" (같은 브라우저면 탭끼리 바로 연결).
- **친구와**: "방 만들기" → "초대 링크 복사"로 보낸다. 방장 브라우저가 서버라서 방장이 탭을 닫으면 방이 사라진다.
- **디버그 (F3)**: 왕복 지연 · 되맞춤 횟수 · 보간 지연. `1` `2` `3` `4` = 가짜 지연 0 · 50 · 150 · 300ms, `P` 예측 끄고 켜기(끄면 지연이 그대로 느껴진다), `I` 보간 끄고 켜기, `B` 봇 추가(방장만).

| 동작 | 키 |
|---|---|
| 이동 | WASD · 방향키 (폰은 화면을 누르고 끌기) |
| 디버그 | F3 · `` ` `` |
| 나가기 | Esc |

## 구조

빌드 없음. ES 모듈 그대로. **서버 코드는 연결 방식과 무관**해서 지금은 방장 브라우저에서 돌고, 나중에 같은 `server.js`를 Node(WebSocket)로 옮긴다.

```
브라우저 (방장)                                   브라우저 (참가자)
 ├ Server   20Hz: 입력 판정 · 스냅샷   ◀── conn ──▶  Client: 내 이동 예측 · 되맞춤 · 다른 사람 보간
 └ Client (같은 페이지 연결)
conn = 같은 페이지(local) │ 같은 브라우저 탭(BroadcastChannel) │ 인터넷(WebRTC, PeerJS 중개)
       + 가짜 지연(latency.js)
```

| 파일 | |
|---|---|
| `src/sim.js` · `src/map.js` | 서버 · 클라이언트가 똑같이 돌리는 이동 · 충돌 · 지도 (결정적) |
| `src/server.js` | 권위 서버: 입력 검증 · 판정 · 스냅샷 |
| `src/client.js` | 예측 · 되맞춤 · 보간 |
| `src/net/` | 연결 방식들과 가짜 지연 |
| `src/render.js` | 480×270 도트 렌더 (지금은 팔레트로 그린 임시 그림) |
| `src/main.js` | 화면 · 입력 · 세션 |
| `sprites.json` | 스프라이트 표. 그림이 생기면 파일만 채운다 |
| `assets/LICENSES.md` | 에셋 출처 · 라이선스 장부 |

## 테스트

```
node --test
```

가짜 시계로 지연 150ms + 흔들림 30%를 걸고 무작위로 4초 걸은 뒤 예측 위치 = 서버 위치(되맞춤 0회)인지, 벽을 뚫지 않는지, 서버가 이상한 입력을 거르는지, 타이머가 반올림돼도 메시지 순서가 안 바뀌는지 등. 푸시하면 GitHub Actions에서도 돈다.

## 알려진 한계 (M0)

- 인터넷 연결은 WebRTC 직접 연결이라 일부 회사 · 학교망에서는 실패할 수 있다 (중계 서버 없음).
- 방장 브라우저가 서버라서 방장이 나가면 방이 끝난다. 계정 · 저장은 M1.
